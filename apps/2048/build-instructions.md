# 2048 게임 — Build 단계 지침

## 목표

`/apps/2048/spec.md`에 승인된 설계를 그대로 구현한다. 반드시 먼저 `spec.md`를 읽고, 그 내용에서 벗어나지 않게 구현한다.

## 범위 (중요)

- 아래 세 파일만 새로 만든다. 그 외 어떤 파일도 생성·수정하지 않는다.
  - `D:\claudecode_exam\my-blog\apps\2048\index.html`
  - `D:\claudecode_exam\my-blog\apps\2048\style.css`
  - `D:\claudecode_exam\my-blog\apps\2048\game.js`
- 블로그 루트의 `index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md` 등은 절대 건드리지 않는다.
- `plan-instructions.md`, `spec.md`는 참고용으로만 읽고 수정하지 않는다.

## 프로젝트 제약 (CLAUDE.md 기준)

- HTML, CSS, JavaScript만 사용. 프레임워크 금지, 번들러/빌드 도구 없이 브라우저에서 바로 동작해야 한다.
- 외부 라이브러리는 사용하지 않는다 (spec.md에서 권장한 대로 순수 vanilla JS로 구현).
- `/apps/2048/` 폴더 안에서 완전히 자체 완결되어야 한다 — 블로그 루트의 CSS/JS를 import하거나 참조하지 않는다.
- 모바일에서도 사용 가능해야 한다 (spec.md의 터치/스와이프, 반응형 요구사항 반영).
- 불필요한 추상화나 설정을 추가하지 않는다. 주석은 WHY가 명확하지 않은 경우에만 최소한으로.

## 구현 시 spec.md에서 특히 지켜야 할 것

- 4x4 보드 상태 표현과 "왼쪽으로 밀기" 공통 함수 + 회전 방식의 이동 처리.
- 한 번의 이동에서 타일은 최대 한 번만 병합 (`2 2 2 2` → `4 4`, `8`이 되면 안 됨).
- 이동 후 실제 변화(`moved === true`)가 있을 때만 새 타일 생성 및 재렌더링.
- 새 타일 값: 90% 확률 2, 10% 확률 4.
- 승리(2048 도달) 오버레이 + "계속하기"/"다시 시작", 패배(이동 불가) 오버레이 + "다시 시작".
- 점수판: 현재 점수 + 최고 점수(localStorage에 최고 점수만 저장).
- 방향키(및 선택적으로 WASD) 입력, `preventDefault()`로 페이지 스크롤 방지.
- 터치 스와이프 지원 (최소 이동 거리 임계값으로 탭과 구분), `touch-action: none`.
- 반응형 레이아웃 (`min(90vw, 420px)` 등 상대 단위, 480px 이하에서 세로 스택), 가로 스크롤 없어야 함.
- 재시작 버튼은 항상 접근 가능한 위치에 배치.
- 최소한의 접근성: 버튼은 실제 `<button>`, 점수판에 `aria-live="polite"`, 보드에 `aria-label`.

## 완료 조건

- 세 파일이 모두 작성되어 `apps/2048/index.html`을 브라우저로 열면(또는 로컬 서버로 서빙하면) 방향키/스와이프로 타일이 밀리고 합쳐지며 점수가 올라가는 동작이 코드 상으로 완결되어 있어야 한다.
- 구현을 마친 뒤, 직접 브라우저에서 정밀 검증하지는 않아도 된다 (그건 Review 단계의 역할). 다만 코드에 명백한 문법 오류나 로직 누락이 없는지 스스로 한 번 검토한다.
- 완료 후 만든 파일 목록과 구현 시 spec.md에서 벗어나거나 판단이 필요했던 부분(있다면)을 간단히 보고한다.
