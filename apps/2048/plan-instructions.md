# 2048 게임 — Plan 단계 지침

## 목표

방향키(↑↓←→)로 숫자 타일을 밀어서 같은 숫자끼리 합치는 2048 퍼즐 게임을 미니 웹앱으로 계획한다. 점수판을 반드시 포함한다.

## 범위 (중요)

- 이 작업은 **계획(Plan) 단계**이며, 코드를 구현하지 않는다. HTML/CSS/JS 파일을 만들지 않는다.
- 산출물은 `/apps/2048/spec.md` 파일 **하나만** 작성한다.
- 그 외 어떤 파일도 생성·수정하지 않는다 (블로그 루트의 index.html, css/, js/, posts/ 등은 절대 건드리지 않는다).

## 프로젝트 제약 (CLAUDE.md 기준)

- HTML, CSS, JavaScript만 사용한다. React/Vue 등 프레임워크 금지.
- 외부 라이브러리 사용은 최소화한다. CDN은 허용되지만, 2048 게임은 순수 vanilla JS로 충분히 구현 가능하므로 라이브러리 없이 구현하는 방향을 권장한다.
- 웹앱은 `/apps/2048/` 폴더 안에서 완전히 자체 완결되어야 한다 (블로그의 다른 CSS/JS를 import/참조하지 않는다).
- 모바일에서도 사용할 수 있어야 한다 — 방향키 외에 터치/스와이프 조작도 고려한다.

## spec.md에 반드시 포함할 내용

1. **게임 개요** — 한두 문장 요약.
2. **파일 구조** — `/apps/2048/` 안에 실제로 만들 파일 목록과 각 파일의 역할 (예: index.html, style.css, game.js 등).
3. **게임 로직 설계**
   - 4x4 그리드 상태 표현 방식
   - 방향키 입력 처리 및 타일 이동/병합 알고리즘 개요 (한 번의 이동에서 병합은 한 번만 일어나야 한다는 2048 규칙 포함)
   - 랜덤 타일 생성 규칙 (게임 시작 시, 매 유효한 이동 후 — 보통 2가 90%, 4가 10%)
   - 승리 조건(2048 타일 생성 시 처리)과 패배 조건(더 이상 이동 불가) 처리 방식
   - 이동했지만 보드에 변화가 없는 경우 새 타일을 생성하지 않는 엣지 케이스 처리
4. **UI/UX 설계**
   - 점수판 표시 방식 (현재 점수, 최고 점수 로컬 저장 여부 등 — localStorage 사용 여부 명시)
   - 타일 스타일링 방침 (숫자별 색상 구분, 최소한의 애니메이션)
   - 모바일 터치/스와이프 지원 방식
   - 재시작 버튼 등 부가 UI 요소
5. **반응형 고려사항** — 작은 화면에서도 보드와 UI가 잘 보이도록.
6. **접근성 최소 고려사항** (예: 포커스 가능한 재시작 버튼 등, 과하게 확장하지 않는다).

과한 설계나 CLAUDE.md 요구사항을 벗어나는 기능(리더보드 서버 연동, 다중 테마 등)은 제안하지 않는다.

- 이 파일 외에는 어떤 파일도 생성/수정하지 않았는지 확인 후 종료.
