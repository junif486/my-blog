# 2048 게임 — Review 결과

검증 대상: `apps/2048/index.html`, `apps/2048/style.css`, `apps/2048/game.js`
검증 방법: `python -m http.server`로 로컬 정적 서버를 띄우고 브라우저 도구(Claude Browser)로 실제 페이지를 열어 콘솔/DOM/localStorage를 확인. 화면 스크린샷 컴포지팅이 이 환경에서 비활성화되어 있어(“Browser pane is not displayed”) 시각적 스크린샷 대신 `read_page`(접근성 트리), `javascript_tool`을 통한 실제 DOM 상태 조회, 그리고 `game.js`의 핵심 함수(`processLine`, `moveBoard`, `canMove`)를 페이지 컨텍스트에 로드해 실행하는 방식으로 동작을 정밀 검증함. 키보드 입력은 OS 레벨 `computer` 키 이벤트가 이 헤드리스 탭에 전달되지 않아, `document.dispatchEvent(new KeyboardEvent(...))`로 실제 `keydown` 리스너를 직접 트리거하는 방식으로 검증(리스너 자체는 실제 게임 코드).

## 검증 항목과 결과

| 항목 | 결과 | 비고 |
|---|---|---|
| 페이지 로드 시 콘솔 에러 없음 | 통과 | 전체 테스트 세션 동안 콘솔 로그/에러 0건 |
| 초기 타일 2개 랜덤 생성 | 통과 | `newGame()`에서 `addRandomTile` 2회 호출 확인, DOM에 타일 2개 생성됨 |
| 방향키(←→↑↓) 이동 | 통과 | `keydown` 디스패치 시 타일이 실제로 이동함을 DOM `transform` 값으로 확인 |
| WASD 보조 입력 | 통과 | 코드 리뷰: `KEY_DIRECTIONS`에 대소문자 w/a/s/d 모두 매핑됨 |
| 병합 규칙: `2 2 2 2` → `4 4` (한 이동에 재병합 없음) | 통과 | `processLine([2,2,2,2])` 직접 실행 결과 `{result:[4,4,0,0], scoreGain:8}` 확인. `8`로 한번에 합쳐지는 오류 없음 |
| 4방향(상/하/좌/우) 이동·병합 로직 | 통과 | `moveBoard(board, dir)`를 up/down/left/right 각각에 대해 알려진 보드로 단위 테스트, 기대값과 일치 |
| 점수 갱신 | 통과 | 실제 플레이(연속 40회 키 입력) 후 SCORE가 병합 값만큼 정확히 누적됨을 확인(예: 236점) |
| BEST 점수 localStorage 영속화 | 통과 | 점수 획득 후 `localStorage.getItem('2048-best-score')` 값 확인 → 페이지 새로고침 후에도 BEST=236 유지, SCORE만 0으로 리셋(스펙 4.1과 일치) |
| 변화 없는 이동 시 새 타일 미생성 | 통과 | `moveBoard`가 이미 왼쪽 끝에 있는 단일 타일에 `left` 적용 시 `moved:false` 반환 확인 + `handleDirection`에 `if (!result.moved) return;` 가드로 렌더링/타일 생성/점수 갱신이 전혀 일어나지 않음을 코드로 확인 |
| 게임오버(더 이상 이동 불가) 판정 | 통과 | 상하좌우 어디로도 병합 불가능한 꽉 찬 보드(`[[2,4,8,16],[4,2,4,2],[2,4,2,4],[4,2,4,2]]`)에 대해 `canMove()` → `false` 확인. 병합 가능한 유사 보드에서는 `true` 확인 |
| 승리(2048 타일) 처리 및 오버레이 | 통과 | 코드 리뷰로 로직 확인(`boardHasTile(board, 2048)` 최초 도달 시 `hasWon=true` + 오버레이 표시), 오버레이 표시/버튼 동작은 DOM에서 `win-overlay.hidden=false` 강제 후 실제 크기(288×288, `display:flex`)로 렌더링됨을 확인. "계속하기" 버튼 클릭 시 오버레이가 정상적으로 다시 숨김 처리됨을 실동작으로 확인 |
| 게임오버 오버레이 및 최종 점수 표시 | 통과 | `lose-overlay` 표시 후 "다시 시작" 버튼 클릭 시 오버레이 숨김 + 새 게임(타일 2개, 점수 0)으로 정상 리셋됨을 실동작으로 확인 |
| 재시작 버튼(상단 툴바) | 통과 | 클릭 시 점수 0, 타일 2개로 리셋 확인 |
| 터치 스와이프 | 통과 | 합성 `TouchEvent`(touchstart/touchend, dx=-250)로 왼쪽 스와이프 시뮬레이션 → 실제 방향키와 동일하게 타일 이동 확인 |
| 모바일 반응형(375px) | 통과 | `document.documentElement.scrollWidth === clientWidth`(가로 스크롤 없음), 툴바가 `flex-direction: column`으로 전환됨 확인 |
| 초협소 화면(320px) | 통과 | 가로 스크롤 없음 확인 |
| 접근성 최소 요건 | 통과 | 재시작/오버레이 버튼이 실제 `<button>` 요소, 점수판에 `aria-live="polite"`, 보드에 `role="img"` + `aria-label="2048 게임 보드"` — 모두 스펙 6절과 일치 |
| 독립성(블로그 CSS/JS 미참조) | 통과 | `index.html`에 `style.css`, `game.js`만 링크, 블로그 루트 `css/`, `js/` 참조 없음. 팔레트도 자체 CSS 변수로 완결 |
| 고정 네온 테마 준수 | 통과 | 라이트 모드, `prefers-color-scheme`, 토글 로직 없음. `--bg`, `--accent`, `--accent-2` 등 CSS 커스텀 프로퍼티로 관리 |

## 발견해서 수정한 문제

없음. 위 항목을 모두 통과했으며, 코드 레벨에서도 실제 버그를 발견하지 못했다. 세 파일에 대한 수정은 이루어지지 않았다.

## 수정하지 않고 남겨둔 사소한 이슈 (우선순위 낮음)

- `document`에 등록된 `keydown` 리스너가 포커스 위치와 무관하게 전역으로 동작하며, `w/a/s/d` 키 입력 시 항상 `preventDefault()`가 호출된다. 현재 페이지에는 텍스트 입력 필드가 없어 실질적 영향은 없지만, 추후 입력 필드가 추가될 경우 타이핑을 막을 수 있다.
- `.scoreboard` 전체(SCORE+BEST)에 `aria-live="polite"`가 걸려 있어, 병합 시 두 값이 동시에 변경되면 스크린리더가 두 텍스트를 함께 읽는다. 기능상 문제는 아니며 스펙 요건은 충족한다.
- 개별 타일 요소에는 별도 접근성 라벨이 없다(스펙 6절에서 "과한 확장은 하지 않는다"고 명시한 범위와 일치하는 의도적 설계).

## 최종 결론

**배포(Embed 단계 진행) 가능.** spec.md의 요구사항(파일 구조, 이동/병합 알고리즘, 랜덤 타일 생성, 승리/패배 조건, 점수판/BEST 영속화, 반응형, 접근성, 독립성)을 모두 충족하며, 실제 브라우저 동작 검증과 핵심 로직 단위 검증에서 문제를 발견하지 못했다. 콘솔 에러 없음, 모바일 폭에서 가로 스크롤 없음, 재시작/스와이프/키보드 입력 모두 정상 동작을 확인했다.
