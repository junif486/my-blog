# 2048 게임 — 설계 스펙 (Plan)

> 이 문서는 **계획 단계 산출물**이다. 실제 구현(HTML/CSS/JS 작성)은 이 문서를 기반으로 별도 단계에서 진행한다.

## 1. 게임 개요

4x4 그리드 위에서 방향키(또는 모바일 스와이프)로 타일을 밀어, 같은 숫자 타일끼리 만나면 하나로 합쳐지는 숫자 퍼즐 게임이다. 합쳐질 때마다 점수가 올라가며, 2048 타일을 만들면 승리, 더 이상 이동할 곳이 없으면 패배로 처리한다.

## 2. 파일 구조

`/apps/2048/` 폴더 안에 아래 세 개 파일만 새로 만든다. 블로그 루트의 `css/`, `js/`, `index.html` 등은 참조하지 않고 완전히 독립적으로 동작한다.

```
apps/2048/
├── index.html   # 게임 페이지 마크업 (보드, 점수판, 재시작 버튼 컨테이너)
├── style.css    # 레이아웃, 타일 색상, 반응형, 최소 애니메이션
└── game.js      # 게임 상태, 입력 처리, 이동/병합 로직, 렌더링
```

- `index.html`: `<head>`에 `style.css` 링크, `<body>` 끝에서 `<script src="game.js" defer></script>` 로드. 프레임워크나 외부 CDN 라이브러리는 사용하지 않는다.
- `style.css`: CSS 커스텀 프로퍼티로 타일 색상 팔레트와 간격 값을 관리한다.
- `game.js`: 순수 vanilla JS(ES 모듈 불필요, 단일 스크립트)로 상태 관리와 DOM 렌더링을 모두 담당한다.

## 3. 게임 로직 설계

### 3.1 상태 표현

- 4x4 보드는 길이 16의 1차원 배열 또는 4개의 행 배열(`number[][]`)로 표현한다. 빈 칸은 `0`으로 표기하고, 채워진 칸은 타일의 숫자 값(2, 4, 8, ... 2048...)을 그대로 저장한다.
- 게임 상태 객체 예시:
  ```
  state = {
    board: number[4][4],   // 0 = 빈 칸
    score: number,         // 현재 점수
    best: number,          // 최고 점수 (localStorage 동기화)
    isGameOver: boolean,
    hasWon: boolean,        // 2048 달성 여부 (달성 후에도 계속 플레이 가능)
  }
  ```
- 렌더링은 상태(state)를 단일 진실 공급원(source of truth)으로 삼고, 매 이동 후 `render(state)` 함수가 DOM을 다시 그리는 단방향 흐름을 따른다.

### 3.2 입력 처리 및 이동/병합 알고리즘

- `keydown` 이벤트에서 `ArrowUp/Down/Left/Right`(및 방향키와 동일하게 동작하는 `w/a/s/d` 선택적 지원)를 감지하고, 방향키의 기본 스크롤 동작은 `preventDefault()`로 막는다.
- 이동 처리는 방향에 관계없이 "왼쪽으로 밀기"라는 하나의 핵심 함수를 기준으로 구현하고, 위/오른쪽/아래 이동은 보드를 회전(또는 전치)한 뒤 동일 함수를 적용하고 다시 되돌리는 방식으로 코드 중복을 줄인다.
- 한 줄(4칸) 이동 알고리즘 개요:
  1. 0(빈 칸)을 제거하고 값들을 한쪽으로 압축한다.
  2. 압축된 배열을 앞에서부터 순회하며, 인접한 두 값이 같고 **아직 이번 이동에서 병합되지 않은 타일**이면 합쳐서 값을 2배로 만들고 점수에 더한다. 병합된 타일은 "이번 이동에서 병합 완료" 표시를 하여 같은 이동 내에서 연쇄 재병합(예: `2 2 2 2` → 한 번에 `8`이 되는 것)이 일어나지 않도록 한다 — 2048 규칙상 한 번의 이동에서 각 타일은 최대 한 번만 병합된다.
  3. 병합 후 다시 0을 채워 4칸을 맞춘다.
  4. 이동 전/후 보드를 비교해 변화 여부(`moved: boolean`)를 함께 반환한다.

### 3.3 랜덤 타일 생성 규칙

- 게임 시작 시 빈 칸 중 무작위 2곳에 타일을 생성한다.
- 매 유효한 이동(보드에 실제 변화가 있었던 이동) 후, 남은 빈 칸 중 무작위 1곳에 새 타일을 생성한다.
- 새 타일 값은 90% 확률로 `2`, 10% 확률로 `4`.

### 3.4 승리/패배 조건

- **승리**: 이동/병합 결과 값이 2048에 도달한 타일이 처음 생기면 `hasWon = true`로 설정하고 승리 안내 오버레이(간단한 메시지 + "계속하기" / "다시 시작" 버튼)를 표시한다. "계속하기"를 선택하면 게임을 계속 진행할 수 있다(2048 이후에도 더 큰 타일을 만드는 것은 허용).
- **패배**: 보드가 가득 찼고(빈 칸 없음) 상하좌우 어느 방향으로도 병합 가능한 인접 쌍이 없을 때 `isGameOver = true`로 설정하고 게임오버 오버레이(최종 점수 + "다시 시작" 버튼)를 표시한다. 이동 가능 여부 판정은 각 방향에 대해 "왼쪽으로 밀기" 시뮬레이션을 수행해 `moved`가 하나라도 `true`이면 아직 이동 가능한 것으로 판단한다.

### 3.5 "이동했지만 변화 없음" 엣지 케이스

- 방향키 입력이 들어와도 해당 방향으로 밀었을 때 보드 배열이 이전과 동일하면(`moved === false`) 새 타일을 생성하지 않고, 점수도 갱신하지 않으며, 렌더링도 다시 하지 않는다(불필요한 리렌더/애니메이션 방지).
- 이 판정은 3.2의 이동 함수가 반환하는 `moved` 플래그로 처리한다.

## 4. UI/UX 설계

### 4.1 점수판

- 상단에 "SCORE"(현재 점수)와 "BEST"(최고 점수) 두 개의 표시 박스를 둔다.
- `localStorage`에 `best score` 값을 저장한다(키 예: `2048-best-score`). 페이지 로드 시 저장된 값을 불러와 표시하고, 현재 점수가 최고 점수를 넘으면 즉시 갱신하여 저장한다.
- 현재 진행 중인 보드 상태 자체는 저장하지 않는다(새로고침 시 새 게임 시작) — 최소 범위 유지를 위해 최고 점수만 영속화한다.

### 4.2 타일 스타일링

- 숫자 값별로 배경색을 CSS 커스텀 프로퍼티로 구분한다(예: 2, 4, 8, 16 ... 2048까지 단계별 색상 팔레트). 블로그 전체의 네온 테마(검정 배경 + 네온 강조색)와 톤을 맞추되, 2048 앱은 자체 팔레트를 독립적으로 정의한다(블로그 CSS를 import하지 않음).
- 타일 등장 시 짧은 scale-in 트랜지션, 병합 시 짧은 pop(확대 후 축소) 트랜지션 정도의 최소한의 CSS 애니메이션만 적용한다(과한 모션 지양).
- 숫자가 커질수록 폰트 크기를 약간 줄여 4자리 이상 숫자도 칸 안에 들어오도록 처리한다.

### 4.3 모바일 터치/스와이프 지원

- `touchstart`에서 시작 좌표를 기록하고, `touchend`에서 종료 좌표와의 차이(dx, dy)를 계산한다.
- `dx`, `dy` 중 절댓값이 더 큰 축을 스와이프 방향으로 판정하고, 최소 스와이프 거리(예: 30px) 이상일 때만 이동으로 인정해 짧은 탭과 스와이프를 구분한다.
- 판정된 방향은 방향키 처리와 동일한 이동 함수를 호출하여 코드를 재사용한다.
- 보드 컨테이너에 `touch-action: none`(또는 `pan-y`가 아닌 값)을 지정해 스와이프 중 브라우저 기본 스크롤/줌 동작과 충돌하지 않도록 한다.

### 4.4 재시작 등 부가 UI

- 점수판 옆(또는 아래)에 "새 게임(Restart)" 버튼을 상시 배치해 언제든 초기 상태로 리셋할 수 있게 한다.
- 게임오버/승리 오버레이 내부에도 동일한 리셋 동작을 하는 버튼을 둔다.
- 조작 방법 안내(방향키 또는 스와이프로 이동)를 헤더 아래 짧은 설명 텍스트로 표시한다.

## 5. 반응형 고려사항

- 보드는 정사각형을 유지하되 뷰포트 폭에 따라 크기가 줄어들도록 `width: min(90vw, 420px)` 형태의 상대 단위 기반 크기 지정을 사용하고, `aspect-ratio: 1 / 1`로 정사각형을 강제한다.
- 그리드 칸 간격과 타일 폰트 크기도 `clamp()` 또는 뷰포트 상대 단위를 사용해 작은 화면에서 자연스럽게 축소되도록 한다.
- 점수판과 버튼은 좁은 화면에서 세로로 쌓이는 flexbox 레이아웃으로 전환되도록 미디어쿼리(예: 480px 이하)를 둔다.
- 전체 페이지에 가로 스크롤이 생기지 않도록 `max-width: 100%`, `overflow-x: hidden`(필요 시) 등을 적용한다.

## 6. 접근성 최소 고려사항

- 재시작 버튼과 오버레이 내 버튼은 실제 `<button>` 요소로 만들어 키보드 포커스와 Enter/Space 활성화가 기본 동작으로 동작하게 한다.
- 점수판 영역에 `aria-live="polite"`를 지정해 점수 변경이 스크린 리더에도 전달되도록 한다.
- 게임 보드 컨테이너에 `role="img"` 또는 `aria-label`(예: "2048 게임 보드")을 지정해 스크린 리더 사용자에게 최소한의 맥락을 제공한다. 타일 하나하나에 대한 상세 접근성 트리 구축 등 과한 확장은 하지 않는다.
