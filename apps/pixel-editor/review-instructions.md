# 픽셀 아트 에디터 — Review 단계 지침

## 목표

Build 단계에서 구현된 `/apps/pixel-editor/` 앱이 `spec.md`대로 실제로 정상 동작하는지 브라우저에서 검증하고, 문제가 있으면 직접 수정한다.

## 범위 (중요)

- 검증 대상: `D:\claudecode_exam\my-blog\apps\pixel-editor\index.html`, `style.css`, `editor.js`
- 문제를 발견해 수정할 때도 이 세 파일 안에서만 수정한다. 블로그 루트의 다른 파일, `apps/2048/`, `CLAUDE.md` 등은 절대 건드리지 않는다.
- 산출물로 `D:\claudecode_exam\my-blog\apps\pixel-editor\review.md`를 작성한다.

## 검증 절차

1. 먼저 `spec.md`를 읽어 원래 설계를 파악한다.
2. 로컬 정적 서버로 `/apps/pixel-editor/index.html`을 브라우저에서 연다 (예: `npx live-server`를 `D:\claudecode_exam\my-blog` 루트에서 실행).
3. 브라우저 콘솔에 에러가 없는지 확인한다.
4. 캔버스를 클릭/드래그해서 실제로 칸이 칠해지는지 확인한다.
5. 팔레트에서 다른 색을 선택하면 이후 그리는 색이 바뀌는지, 선택된 스와치에 표시(글로우/aria-pressed)가 되는지 확인한다.
6. 커스텀 색상(`<input type="color">`)을 바꾸면 그리기 색이 바뀌는지 확인한다.
7. 지우개 선택 후 칠하면 해당 칸이 빈 칸(체커보드)으로 바뀌는지 확인한다.
8. "전체 지우기" 버튼이 확인(confirm) 후 격자를 초기화하는지 확인한다.
9. "PNG로 저장" 버튼을 눌러 실제로 다운로드가 트리거되는지 확인한다 (가능하다면 다운로드된 이미지가 256x256이고, 칠하지 않은 칸이 투명한지 코드/동작으로 확인한다).
10. 브라우저 창 크기를 모바일 폭(예: 375px)으로 줄여 레이아웃이 깨지지 않는지, 가로 스크롤이 생기지 않는지, 터치 드래그로도 그릴 수 있을 만한 구조인지(코드 리뷰로) 확인한다.
11. "블로그로 돌아가기" 링크가 실제로 블로그 메인으로 이동하는지 확인한다.
12. 발견한 문제는 세 파일 안에서 직접 수정하고, 수정 후 다시 확인한다.

## review.md에 포함할 내용

- 검증한 항목과 결과 (통과/실패, 실패 시 원인)
- 발견해서 수정한 문제 목록 (있다면)
- 수정하지 않고 남겨둔 사소한 이슈나 개선 여지 (있다면, 우선순위 낮음으로 표시)
- 최종 결론: 배포(Embed 단계 진행) 가능 여부

## 완료 조건

- `review.md` 작성 완료.
- 발견된 문제는 가능한 범위 내에서 수정 완료.
- 지정된 세 파일과 review.md 외에는 어떤 파일도 생성/수정하지 않는다.
