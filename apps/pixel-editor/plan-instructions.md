# 픽셀 아트 에디터 — Plan 단계 지침

## 목표

16x16 격자에 도트(픽셀)를 찍어 그림을 그리고, 완성한 그림을 PNG 파일로 저장할 수 있는 픽셀 아트 에디터를 미니 웹앱으로 계획한다. 색상 팔레트를 반드시 포함한다.

## 범위 (중요)

- 이 작업은 **계획(Plan) 단계**이며, 코드를 구현하지 않는다.
- 산출물은 `/apps/pixel-editor/spec.md` 파일 **하나만** 작성한다.
- 그 외 어떤 파일도 생성·수정하지 않는다 (블로그 루트의 index.html, css/, js/, posts/, 이미 완성된 apps/2048/ 등은 절대 건드리지 않는다).

## 프로젝트 제약 (CLAUDE.md 기준)

- HTML, CSS, JavaScript만 사용한다. 프레임워크 금지.
- 외부 라이브러리 사용은 최소화한다. CDN은 허용되지만, 이 에디터는 순수 vanilla JS + Canvas API로 충분히 구현 가능하므로 라이브러리 없이 구현하는 방향을 권장한다.
- 웹앱은 `/apps/pixel-editor/` 폴더 안에서 완전히 자체 완결되어야 한다.
- 모바일에서도 사용할 수 있어야 한다 — 마우스 드래그뿐 아니라 터치(탭/드래그)로도 그릴 수 있어야 한다.
- 이미 만들어진 `/apps/2048/`에는 "블로그로 돌아가기" 링크가 있다. 이 에디터에도 동일하게 블로그 메인으로 돌아가는 링크(또는 종료 버튼)를 반드시 포함한다.

## spec.md에 반드시 포함할 내용

1. **앱 개요** — 한두 문장 요약.
2. **파일 구조** — `/apps/pixel-editor/` 안에 실제로 만들 파일 목록과 역할 (예: index.html, style.css, editor.js 등).
3. **캔버스/격자 설계**
   - 16x16 논리 격자를 어떻게 표현하고 렌더링할지 (HTML `<canvas>` 권장, 또는 grid의 DOM 셀 방식도 가능 — 선택하고 이유를 적는다).
   - 격자 셀 하나하나를 클릭/드래그/터치로 색칠하는 상호작용 처리 방식.
   - 그리드 셀 크기가 화면 크기에 따라 반응형으로 조절되는 방식.
4. **색상 팔레트 설계**
   - 기본 제공 색상 목록 (몇 개, 어떤 색인지).
   - 현재 선택된 색상 표시 방식.
   - 커스텀 색상 선택 지원 여부 (예: `<input type="color">` 추가 여부) — 최소 기능으로 넣을지 결정.
   - 지우개(투명/배경색) 기능 포함 여부.
5. **도구/부가 기능** (최소 범위로 판단해서 결정, 과한 기능 나열 금지)
   - 전체 지우기(Clear) 버튼.
   - PNG로 저장 — 16x16 논리 픽셀을 실제로 어떤 해상도의 PNG로 내보낼지(예: 1px=1px 원본 그대로 저장할지, 보기 좋게 확대해서 저장할지) 결정하고 근거를 적는다. `canvas.toBlob()` 또는 `toDataURL()` + 다운로드 링크 방식 등 구체적 구현 방식을 명시한다.
6. **UI/UX 설계**
   - 전체 레이아웃 배치 (캔버스, 팔레트, 도구 버튼들의 배치).
   - 블로그로 돌아가기 링크 위치.
   - 네온 테마와 톤을 맞추되 자체 CSS 커스텀 프로퍼티로 독립적으로 관리 (blog 루트 CSS를 참조하지 않음).
7. **반응형 고려사항** — 작은 화면에서도 격자와 팔레트가 잘 보이고 조작 가능하도록.
8. **접근성 최소 고려사항** (버튼 포커스 가능 등, 과하게 확장하지 않는다).

과한 설계나 요구사항을 벗어나는 기능(레이어, 실행취소 스택, 애니메이션 프레임 등)은 제안하지 않는다. 딱 "16x16 격자 + 팔레트 + PNG 저장" 요구사항에 집중한다.

- 이 파일 외에는 어떤 파일도 생성/수정하지 않았는지 확인 후 종료.
