# 픽셀 아트 에디터 — 설계 스펙 (Plan)

> 이 문서는 **계획 단계 산출물**이다. 실제 구현(HTML/CSS/JS 작성)은 이 문서를 기반으로 별도 단계에서 진행한다.

## 1. 앱 개요

16x16 격자에 마우스 클릭·드래그 또는 터치로 도트를 찍어 그림을 그리고, 색상 팔레트에서 색을 고르며, 완성한 그림을 PNG 파일로 저장할 수 있는 미니 픽셀 아트 에디터다.

## 2. 파일 구조

`/apps/pixel-editor/` 폴더 안에 아래 세 파일만 새로 만든다. 블로그 루트의 `css/`, `js/`, `index.html`이나 `/apps/2048/`은 참조·수정하지 않고 완전히 독립적으로 동작한다.

```
apps/pixel-editor/
├── index.html   # 페이지 마크업 (캔버스, 팔레트, 도구 버튼 컨테이너)
├── style.css    # 레이아웃, 네온 테마(독자 CSS 커스텀 프로퍼티), 반응형
└── editor.js    # 격자 상태, 입력(마우스/터치) 처리, 렌더링, PNG 내보내기
```

- `index.html`: `<head>`에 `style.css` 링크, `<body>` 끝에서 `<script src="editor.js" defer></script>` 로드. 프레임워크·외부 CDN 라이브러리 사용 안 함.
- `style.css`: `--bg`, `--accent`, `--accent-2` 등 이 앱 전용 CSS 커스텀 프로퍼티를 자체적으로 정의한다(블로그 루트 CSS를 import하지 않음).
- `editor.js`: 순수 vanilla JS 단일 스크립트로 상태 관리, 렌더링, 이벤트 처리, PNG 내보내기를 모두 담당한다.

## 3. 캔버스/격자 설계

### 3.1 표현 방식 — `<canvas>` 채택

DOM 그리드(256개의 `<div>` 셀) 대신 `<canvas>` 하나로 16x16 격자를 그린다. 이유:

- **PNG 저장이 네이티브로 가능하다.** `canvas.toBlob()` / `toDataURL()`을 그대로 쓸 수 있어, DOM 셀 방식이었다면 필요했을 별도의 "DOM → 이미지" 변환 라이브러리(html2canvas 등, 외부 라이브러리 금지 원칙에 위배)가 필요 없다.
- 256개의 개별 DOM 요소와 각각의 이벤트 리스너보다, 캔버스 하나 + 좌표 계산 방식이 더 가볍고 단순하다.
- 픽셀 아트 특성상 사각형을 정확히 채우는 `fillRect` 그리기가 자연스럽다.

### 3.2 논리 격자와 렌더링

- 논리 상태는 16x16 크기의 1차원 배열(`grid = new Array(256)`)로 표현한다. 각 칸의 값은 `null`(빈 칸/지우개 상태) 또는 색상 문자열(`"#ff2fd0"` 형태)이다.
- 렌더링 함수 `render()`는 매번 캔버스 전체를 지우고(`clearRect`), `grid`를 순회하며 각 칸을 `fillRect(x, y, cellSize, cellSize)`로 그린다. 빈 칸(`null`)은 배경보다 살짝 밝은 체커보드 패턴(2색 교차 사각형)으로 그려 "투명/미채색" 상태임을 시각적으로 구분한다 — 이 체커보드는 화면 표시용일 뿐 PNG로는 내보내지 않는다.
- 캔버스의 실제 픽셀 크기(`canvas.width`/`canvas.height`)는 CSS 표시 크기와 `devicePixelRatio`를 곱한 값으로 설정해 고해상도 화면에서도 선명하게 그려지도록 한다. `fillRect`로 셀 단위를 직접 그리므로 이미지 확대에 따른 블러(blur) 문제가 없다(이미지 스무딩을 쓰지 않음).

### 3.3 클릭/드래그/터치 상호작용

- 마우스와 터치를 하나의 코드 경로로 처리하기 위해 **Pointer Events**(`pointerdown`, `pointermove`, `pointerup`, `pointercancel`)를 사용한다. 마우스 클릭, 마우스 드래그, 터치 탭, 터치 드래그를 모두 동일한 핸들러로 처리할 수 있어 별도의 `touchstart`/`mousedown` 분기가 필요 없다.
- `pointerdown` 시 `isDrawing = true`로 설정하고 좌표에 해당하는 칸을 즉시 칠한다(탭 한 번으로도 칠해지도록).
- `pointermove` 중 `isDrawing`이 true면, 이벤트 좌표를 캔버스 기준 상대 좌표로 변환한 뒤 `cellSize`로 나누어 행/열 인덱스를 구하고, 범위(0~15)를 벗어나면 무시한다. 직전에 칠한 칸과 인덱스가 같으면 다시 그리지 않아(중복 렌더 방지) 성능을 아낀다.
- `pointerup`/`pointercancel`(포인터가 캔버스 밖으로 나가거나 취소된 경우 포함)에서 `isDrawing = false`.
- 캔버스에 `touch-action: none`을 지정해 드래그 중 브라우저 기본 스크롤/줌과 충돌하지 않도록 한다.
- 셀 하나를 칠할 때마다 캔버스 전체를 다시 그리는 방식(`render()` 전체 재호출)으로 충분하다 — 16x16(256칸) 규모는 매우 가벼워 성능 문제가 없으므로 부분 갱신 최적화는 하지 않는다(과설계 지양).

### 3.4 반응형 셀 크기

- 캔버스의 CSS 표시 크기는 `width: min(90vw, 480px)`처럼 뷰포트 기준 상대 크기로 지정하고, `aspect-ratio: 1 / 1`로 정사각형을 유지한다.
- 셀 크기(`cellSize`)는 하드코딩하지 않고 `캔버스 표시 크기 / 16`으로 매 렌더링 시 동적으로 계산한다.
- `window.resize` 이벤트(디바운스 적용)에서 캔버스의 실제 픽셀 크기를 다시 계산하고 `render()`를 재호출해, 화면 크기가 바뀌어도 격자가 항상 캔버스에 꽉 차도록 한다.

## 4. 색상 팔레트 설계

### 4.1 기본 제공 색상 (16색)

네온 테마와 어울리면서도 실제 픽셀 아트 작업에 쓸 만한 균형 잡힌 16색 고정 팔레트를 기본 제공한다:

```
검정 #000000, 흰색 #ffffff, 회색 #888888, 진회색 #333333,
빨강 #ff3b3b, 주황 #ff8c1a, 노랑 #ffe135, 연두 #9dff1a,
초록 #1aff6f, 청록 #0ff0fc, 파랑 #1a6bff, 남색 #3a1aff,
보라 #a01aff, 분홍 #ff2fd0, 갈색 #8a5a2b, 살구색 #ffcba4
```

이 중 청록(`#0ff0fc`)과 분홍(`#ff2fd0`)은 블로그 전체 네온 테마의 `--accent`/`--accent-2`와 톤을 맞춘 것이다.

### 4.2 선택 색상 표시

- 팔레트는 16개의 `<button class="swatch">` 요소를 4x4 그리드로 배치하고, `background-color`를 각 색상으로 지정한다.
- 현재 선택된 스와치에는 `aria-pressed="true"`와 함께 `box-shadow`(네온 글로우, `--accent` 색) 테두리를 주어 시각적으로 구분한다.
- 선택된 색상은 별도의 "현재 색상 미리보기" 박스(작은 사각형)에도 동시에 표시해, 팔레트를 스크롤/확인하지 않아도 현재 그릴 색을 바로 알 수 있게 한다.

### 4.3 커스텀 색상 지원

- `<input type="color">` 하나를 팔레트 옆에 최소 기능으로 추가한다. 값이 바뀌면(`input` 이벤트) 해당 색이 즉시 "현재 색상"으로 설정된다.
- 별도의 커스텀 팔레트 저장/관리(색상 추가 목록 등)는 만들지 않는다 — 요구사항 범위를 벗어나는 과설계이므로 색상 선택 그 자체만 지원한다.

### 4.4 지우개 기능

- 팔레트 옆에 "지우개" 버튼을 하나 둔다. 선택 시 현재 그리기 색상을 `null`(빈 칸)로 설정해, 이후 칠하는 칸은 빈 칸(체커보드 표시, PNG에서는 투명)이 된다.
- 지우개도 다른 색상 스와치와 동일한 선택 상태 표시 방식(`aria-pressed`, 글로우 테두리)을 공유한다.

## 5. 도구/부가 기능

- **전체 지우기(Clear)**: 버튼 클릭 시 `grid` 배열 전체를 `null`로 초기화하고 다시 렌더링한다. 되돌리기 기능은 만들지 않으므로(요구사항 범위 밖), 클릭 시 `confirm()` 네이티브 대화상자로 한 번 확인을 받아 실수 방지한다.
- **PNG로 저장**:
  - 16x16 원본 그대로(1px = 1px)는 대부분의 이미지 뷰어에서 너무 작게 보이므로, **16배 확대(256x256px)**한 PNG로 내보낸다. 픽셀 아트의 각진 경계를 유지하기 위해 확대는 보간(smoothing) 없이 각 논리 셀을 `fillRect(x*16, y*16, 16, 16)`로 그리는 방식으로 수행한다(이미지 스케일링이 아니라 셀 단위 재그리기이므로 자연히 계단 현상 없는 선명한 픽셀이 나온다).
  - 구현: 화면에 보이지 않는 별도의 오프스크린 `<canvas>`(256x256)를 만들어 `grid`를 순회하며 색이 있는 칸만 `fillRect`로 그린다(빈 칸은 그리지 않아 PNG에서 투명하게 남는다 — 배경색을 미리 채우지 않음).
  - `offscreenCanvas.toBlob(blob => { ... }, 'image/png')`로 PNG Blob을 생성하고, `URL.createObjectURL(blob)`으로 만든 URL을 임시 `<a download="pixel-art.png">` 요소의 `href`에 연결해 클릭을 트리거하는 방식으로 다운로드한다. 다운로드 트리거 후 `URL.revokeObjectURL()`로 메모리를 해제한다.
  - `toBlob`은 비동기이므로 저장 버튼은 콜백 완료 후 다운로드를 실행한다(별도 라이브러리 불필요, 표준 Canvas API만 사용).

## 6. UI/UX 설계

### 6.1 레이아웃 배치

- 상단 헤더: 블로그로 돌아가기 링크(좌측 상단, `/apps/2048/`과 동일한 패턴) + 앱 제목 "픽셀 아트 에디터" + 짧은 사용법 안내 문구.
- 헤더 아래 메인 영역은 두 블록으로 구성:
  1. **캔버스 블록**(좌측 또는 상단): 16x16 픽셀 캔버스.
  2. **컨트롤 패널**(우측 또는 하단): 현재 색상 미리보기, 16색 팔레트, 커스텀 색상 입력, 지우개 버튼, "전체 지우기" 버튼, "PNG로 저장" 버튼.
- 데스크톱(넓은 화면)에서는 `flex-direction: row`로 캔버스와 컨트롤 패널을 좌우로 배치하고, 좁은 화면에서는 `flex-direction: column`으로 세로로 쌓는다(미디어쿼리 기준은 7절 참고).

### 6.2 블로그로 돌아가기 링크

- 헤더 좌측 상단에 `<a class="back-link" href="../../index.html">← 블로그로 돌아가기</a>`를 `/apps/2048/index.html`과 동일한 위치·문구 패턴으로 배치한다.

### 6.3 네온 테마

- `style.css`에서 `--bg`(검정 배경), `--accent`(청록 계열), `--accent-2`(분홍 계열) 등 이 앱만의 CSS 커스텀 프로퍼티를 독립적으로 정의한다. 블로그 루트 CSS 파일을 링크하거나 값을 참조하지 않는다.
- 제목과 "현재 선택된 팔레트 스와치" 등 포인트 요소에만 `text-shadow`/`box-shadow` 네온 글로우를 적용하고, 본문 안내 문구는 `--muted` 톤의 은은한 색으로 가독성을 유지한다.

## 7. 반응형 고려사항

- 캔버스는 `width: min(90vw, 480px)` + `aspect-ratio: 1 / 1`로 뷰포트에 맞춰 축소되는 정사각형을 유지한다.
- 컨트롤 패널(팔레트 버튼, 도구 버튼)은 flexbox/grid + 상대 단위로 구성해, 좁은 화면에서도 스와치가 잘리지 않고 줄바꿈되도록 한다(`flex-wrap: wrap` 또는 그리드 `repeat(auto-fit, minmax(...))`).
- 약 640px 이하 화면에서는 미디어쿼리로 레이아웃을 세로 스택(캔버스 위, 컨트롤 패널 아래)으로 전환한다.
- 팔레트 스와치 버튼은 터치로 누르기 쉽도록 최소 36~40px 크기를 확보한다.
- 페이지 전체에 `overflow-x: hidden`(또는 `max-width: 100%`)을 적용해 어떤 화면 크기에서도 가로 스크롤이 생기지 않도록 한다.

## 8. 접근성 최소 고려사항

- 팔레트 스와치, 지우개, 전체 지우기, PNG 저장 버튼은 모두 실제 `<button>` 요소로 만들어 키보드 포커스(Tab)와 Enter/Space 활성화가 기본 동작으로 지원되도록 한다.
- 각 팔레트 스와치 버튼에 `aria-label`(예: "색상: 청록")과 `aria-pressed`(선택 상태)를 지정한다.
- 캔버스에는 `role="img"`와 `aria-label="16x16 픽셀 아트 캔버스"`를 지정해 스크린 리더 사용자에게 최소한의 맥락을 제공한다(칸 하나하나의 상세 접근성 트리 구축 등은 과한 확장이므로 하지 않는다).
- 커스텀 색상 `<input type="color">`에는 `aria-label="커스텀 색상 선택"`을 지정한다.
