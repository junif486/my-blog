# 테트리스 게임 — Review 단계 지침

## 목표

Build 단계에서 구현된 `/apps/tetris/` 게임이 `spec.md`대로 실제로 정상 동작하는지 브라우저에서 독립적으로 검증하고, 문제가 있으면 직접 수정한다. Build 서브에이전트도 자체적으로 일부 검증했지만, 당신은 이를 그대로 신뢰하지 말고 처음부터 다시 검증한다.

## 범위 (중요)

- 검증 대상: `D:\claudecode_exam\my-blog\apps\tetris\index.html`, `style.css`, `game.js`
- 문제를 발견해 수정할 때도 이 세 파일 안에서만 수정한다. 블로그 루트, `apps/2048/`, `apps/pixel-editor/`, `CLAUDE.md` 등은 절대 건드리지 않는다.
- 산출물로 `D:\claudecode_exam\my-blog\apps\tetris\review.md`를 작성한다.

## 검증 절차

1. 먼저 `spec.md`를 읽어 원래 설계를 파악한다.
2. 로컬 정적 서버로 `/apps/tetris/index.html`을 브라우저에서 연다 (`npx live-server`를 `D:\claudecode_exam\my-blog` 루트에서 실행하기 전에, 이미 실행 중인 서버가 있는지 먼저 확인해 포트 충돌을 피한다).
3. 브라우저 콘솔에 에러가 없는지 확인한다.
4. 블록이 자동으로 낙하하는지, 좌우 이동/회전/소프트드롭/하드드롭 키가 모두 정상 동작하는지 확인한다.
5. 회전 시 벽/바닥 근처에서 단순 킥이 동작하는지(회전이 막히지 않고 옆으로 밀리는지) 확인한다.
6. 한 줄을 채웠을 때 그 줄이 사라지고 점수가 오르는지 확인한다 (직접 플레이가 어렵다면 board 배열을 조작해 줄을 강제로 채운 뒤 라인클리어 로직을 코드/DOM 상태로 검증해도 된다).
7. 다음 블록 미리보기가 실제로 다음에 나올 블록과 일치하는지 확인한다.
8. 일시정지(P) 시 낙하가 멈추고 오버레이가 뜨는지, 재개 시 정상 복귀하는지 확인한다.
9. 게임오버 상황(보드를 가득 채워 스폰 위치 충돌)이 발생했을 때 오버레이와 최종 점수가 표시되는지 확인한다. "다시 시작"이 정상 동작하는지 확인한다.
10. 최고 점수가 `localStorage`에 저장되고 새로고침 후에도 유지되는지 확인한다.
11. 모바일 터치 버튼(좌/우/회전/소프트드롭)이 실제로 동작하는지, 특히 버튼을 누르고 있을 때 반복 이동이 되고 뗐을 때 확실히 멈추는지(interval이 누수 없이 정리되는지) 확인한다 — Build 단계에서 유사한 타이머 누수 버그가 한 번 발견됐으니 특히 꼼꼼히 본다.
12. 브라우저 창 크기를 모바일 폭(예: 375px)으로 줄여 레이아웃이 깨지지 않는지, 가로 스크롤이 생기지 않는지 확인한다.
13. "블로그로 돌아가기" 링크가 실제로 블로그 메인으로 이동하는지 확인한다.
14. 발견한 문제는 세 파일 안에서 직접 수정하고, 수정 후 다시 확인한다.

## review.md에 포함할 내용

- 검증한 항목과 결과 (통과/실패, 실패 시 원인)
- 발견해서 수정한 문제 목록 (있다면)
- 수정하지 않고 남겨둔 사소한 이슈나 개선 여지 (있다면, 우선순위 낮음으로 표시)
- 최종 결론: 배포(Embed 단계 진행) 가능 여부

## 완료 조건

- `review.md` 작성 완료.
- 발견된 문제는 가능한 범위 내에서 수정 완료.
- 지정된 세 파일과 review.md 외에는 어떤 파일도 생성/수정하지 않는다.
