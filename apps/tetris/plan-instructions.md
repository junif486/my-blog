# 테트리스 게임 — Plan 단계 지침

## 목표

떨어지는 테트로미노 블록을 좌우 이동/회전시키고 줄을 채워 없애는 고전 테트리스 게임을 미니 웹앱으로 계획한다.

## 범위 (중요)

- 이 작업은 **계획(Plan) 단계**이며, 코드를 구현하지 않는다.
- 산출물은 `/apps/tetris/spec.md` 파일 **하나만** 작성한다.
- 그 외 어떤 파일도 생성·수정하지 않는다 (블로그 루트, 이미 완성된 `/apps/2048/`, `/apps/pixel-editor/` 등은 절대 건드리지 않는다).

## 프로젝트 제약 (CLAUDE.md 기준)

- HTML, CSS, JavaScript만 사용. 프레임워크 금지, 번들러/빌드 도구 없이 브라우저에서 바로 동작해야 한다.
- 외부 라이브러리는 최소화한다 — 테트리스는 순수 vanilla JS + Canvas(또는 DOM 그리드)로 충분히 구현 가능하므로 라이브러리 없이 구현하는 방향을 권장한다.
- 웹앱은 `/apps/tetris/` 폴더 안에서 완전히 자체 완결되어야 한다.
- 모바일에서도 사용할 수 있어야 한다 — 방향키 외에 화면 터치 버튼(좌/우/회전/소프트드롭 등) 조작을 고려한다.
- 기존 `/apps/2048/`, `/apps/pixel-editor/`처럼 헤더에 "블로그로 돌아가기" 링크(`<a class="back-link" href="../../index.html">← 블로그로 돌아가기</a>`)를 반드시 포함한다.

## spec.md에 반드시 포함할 내용

1. **게임 개요** — 한두 문장 요약.
2. **파일 구조** — `/apps/tetris/` 안에 실제로 만들 파일 목록과 역할.
3. **보드/블록 설계**
   - 보드 크기(표준 10x20 권장)와 상태 표현 방식.
   - 7종 테트로미노(I, O, T, S, Z, J, L) 모양과 회전 상태 표현 방식(회전 시스템은 단순화해도 되며, 그 근거를 적는다 — SRS 전체 구현은 과설계일 수 있음).
   - 렌더링 방식(Canvas 권장, 이유 포함).
4. **게임 로직 설계**
   - 블록 낙하 타이밍(중력, 레벨에 따른 속도 증가 여부는 최소 범위로 결정).
   - 좌우 이동, 회전, 소프트 드롭/하드 드롭 처리.
   - 충돌 판정(벽/바닥/다른 블록).
   - 줄이 가득 찼을 때 제거 및 점수 처리.
   - 다음 블록 미리보기 포함 여부(포함 권장, 최소 구현으로).
   - 게임오버 조건과 처리.
5. **입력 처리**
   - 키보드: 방향키(좌/우/아래/회전용 위 또는 스페이스 등) 매핑.
   - 모바일: 화면 터치 버튼 배치(최소한으로 — 좌, 우, 회전, 소프트드롭 정도).
6. **UI/UX 설계**
   - 점수/레벨/다음 블록 표시 위치.
   - 일시정지/재시작 버튼.
   - 게임오버 오버레이.
   - 블로그로 돌아가기 링크 위치.
   - 네온 테마(기존 두 앱과 톤은 맞추되 자체 CSS 커스텀 프로퍼티로 독립 관리).
7. **반응형 고려사항** — 작은 화면에서도 보드와 컨트롤이 잘 보이고 조작 가능하도록.
8. **접근성 최소 고려사항**.

과한 설계(홀드 기능, 고스트 피스, 온라인 랭킹, 사운드 등)는 제안하지 않는다. 고전 테트리스의 핵심(낙하, 이동, 회전, 줄 제거, 점수)에 집중한다.
