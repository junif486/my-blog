# 테트리스 게임 — 설계 스펙 (Plan)

> 이 문서는 **계획 단계 산출물**이다. 실제 구현(HTML/CSS/JS 작성)은 이 문서를 기반으로 별도 단계에서 진행한다.

## 1. 게임 개요

10x20 보드 위에서 7종 테트로미노 블록이 일정 주기로 자동 낙하하며, 플레이어는 좌우 이동/회전/소프트·하드 드롭으로 블록을 조작해 가로 한 줄을 빈칸 없이 채운다. 줄이 채워지면 제거되며 점수가 오르고, 쌓인 블록이 보드 상단을 넘으면 게임오버가 된다.

## 2. 파일 구조

`/apps/tetris/` 폴더 안에 아래 세 개 파일만 새로 만든다. 블로그 루트의 `css/`, `js/`, `index.html`이나 다른 앱(`/apps/2048/`, `/apps/pixel-editor/`)은 참조하지 않고 완전히 독립적으로 동작한다.

```
apps/tetris/
├── index.html   # 게임 페이지 마크업 (보드 캔버스, 사이드 패널, 터치 컨트롤, 오버레이)
├── style.css    # 레이아웃, 네온 테마 색상, 반응형, 최소 애니메이션
└── game.js      # 게임 상태, 타이머, 입력 처리, 충돌/회전/라인클리어 로직, 렌더링
```

- `index.html`: `<head>`에 `style.css` 링크, `<body>` 끝에서 `<script src="game.js" defer></script>` 로드. 프레임워크나 외부 CDN 라이브러리는 사용하지 않는다.
- `style.css`: CSS 커스텀 프로퍼티로 배경/네온 강조색과 테트로미노별 색상 팔레트를 관리한다. 다른 앱의 CSS를 import하지 않고 자체 변수만 정의한다.
- `game.js`: 순수 vanilla JS(모듈 불필요, 단일 스크립트)로 상태 관리, 낙하 타이머, 입력 처리, Canvas 렌더링을 모두 담당한다.

## 3. 보드/블록 설계

### 3.1 보드 크기와 상태 표현

- 표준 크기인 **10열 x 20행** 보드를 사용한다.
- 보드 상태는 `board[20][10]` 형태의 2차원 배열로 표현한다. 빈 칸은 `0`(또는 `null`), 채워진 칸은 해당 칸을 채운 테트로미노의 색상 인덱스(예: `1`~`7`)를 저장한다. 렌더링 시 이 인덱스를 색상 팔레트에 매핑한다.
- 현재 떨어지는 블록은 보드 배열과 별도로 `currentPiece = { type, rotation, x, y }` 형태의 상태로 관리한다. `x, y`는 블록의 기준점(피벗) 셀 좌표다. 매 프레임 보드를 그릴 때 고정된 칸(board)과 현재 낙하 중인 블록(currentPiece)을 합쳐서 렌더링하며, 블록이 바닥에 닿아 고정될 때만 board 배열에 실제로 값을 기록한다.

### 3.2 테트로미노 모양과 회전 시스템

- 7종 블록(I, O, T, S, Z, J, L)은 각각 4x4 셀 기준의 좌표 배열로 정의한다. 각 블록 타입마다 회전 상태 0~3(4방향)의 셀 좌표를 미리 하드코딩한 상수 테이블(`SHAPES` 객체)로 관리한다 — 회전할 때마다 좌표를 계산하지 않고 사전 정의된 4개 배열 중 하나를 선택하는 방식이다.
- **회전 시스템은 SRS(Super Rotation System)의 벽차기(wall kick) 테이블 전체를 구현하지 않고 단순화한다.** 근거:
  - SRS는 회전 실패 시 최대 5가지 오프셋을 순차 시도하는 복잡한 킥 테이블이 필요해 학습/구현 비용이 크고, 이 프로젝트는 "고전 테트리스의 핵심(낙하/이동/회전/줄 제거/점수)"에 집중하는 것이 목표이므로 과설계에 해당한다.
  - 대신 **단순 킥(simple kick)** 방식을 사용한다: 회전 후 해당 위치가 벽/바닥/다른 블록과 충돌하면, `x` 좌표를 -1, +1, -2, +2 순서로 한 칸씩 시도해 충돌하지 않는 첫 위치로 옮긴다(모두 실패하면 회전을 취소한다). O 블록은 회전해도 모양이 바뀌지 않으므로 회전 로직을 그대로 통과시키되 좌표 테이블상 동일 모양을 반환한다.
  - 이 단순화로 SRS 특유의 T-스핀 같은 고급 기법은 지원하지 않지만, 일반적인 플레이(좁은 틈에서의 기본 회전 포함)에는 문제가 없다.

### 3.3 렌더링 방식

- **Canvas**를 사용한다. 이유:
  - 보드가 10x20=200칸이며 매 낙하 틱마다 다시 그려야 하는데, DOM 그리드 방식은 200개 엘리먼트의 스타일을 매번 갱신해야 해 비효율적이고, Canvas는 `clearRect` 후 채워진 칸만 순회하며 `fillRect`로 그리는 것이 더 가볍고 코드도 단순하다.
  - 네온 글로우 효과(`shadowBlur`, `shadowColor`)를 블록 테두리에 적용하기 쉽다.
- 보드용 캔버스 하나와, "다음 블록" 미리보기용 작은 캔버스 하나를 둔다. 셀 하나의 픽셀 크기는 CSS로 캔버스 전체 크기를 정하고 JS에서 `canvas.width / 10`으로 셀 크기를 계산해 반응형 크기 변경에 대응한다.

## 4. 게임 로직 설계

### 4.1 블록 낙하 타이밍

- `setInterval`이 아닌, 매 프레임 `requestAnimationFrame` 안에서 경과 시간을 누적해 낙하 간격(`dropInterval`)을 넘으면 블록을 한 칸 내리는 방식을 사용한다(일시정지/재개 시 타이머 오차가 적고, 하드 드롭 등 즉시 동작과 충돌하지 않기 때문).
- **레벨에 따른 속도 증가는 최소 범위로 포함한다**: 제거한 총 줄 수를 10으로 나눈 값을 레벨로 삼고, 레벨이 오를 때마다 `dropInterval`을 일정 비율(예: 레벨당 약 10% 단축, 최소 하한값 존재)로 줄인다. 복잡한 공식(가이드라인 표준 프레임 테이블 등) 없이 단순 감소 공식 하나로 충분하다.

### 4.2 이동/회전/드롭 처리

- **좌우 이동**: 방향키 입력 시 `x ± 1` 위치가 충돌하지 않으면 이동.
- **회전**: 3.2의 단순 킥 방식으로 처리.
- **소프트 드롭**: 아래 방향키를 누르는 동안 낙하 간격을 단축(예: 고정 간격의 1/20 또는 즉시 한 칸씩)해 더 빠르게 내려가도록 하며, 소프트 드롭으로 내려간 칸 수만큼 약간의 추가 점수를 준다.
- **하드 드롭**: 스페이스바 입력 시 충돌 직전까지 한 번에 떨어뜨리고 즉시 블록을 고정 처리한다. 떨어진 칸 수에 비례한 추가 점수를 준다.

### 4.3 충돌 판정

- 공통 `isValidPosition(shape, x, y)` 함수 하나로 이동/회전/드롭 모두 처리한다: 블록을 이루는 각 셀에 대해 (1) 보드 가로 범위(0~9) 밖인지, (2) 세로 범위(바닥, 20행) 밖인지, (3) 해당 칸에 이미 고정된 블록이 있는지를 확인해 셋 중 하나라도 해당하면 `false`를 반환한다.

### 4.4 줄 제거 및 점수 처리

- 블록이 고정될 때마다 보드를 위에서부터 훑어 **모든 칸이 채워진 행**을 찾는다. 찾은 행들을 배열에서 제거하고, 그만큼 보드 맨 위에 빈 행을 새로 추가해 위쪽 블록들이 자연스럽게 한 칸씩 내려오게 한다(배열 `splice` + `unshift` 조합).
- 점수는 한 번에 제거한 줄 수에 따라 차등 지급한다(고전 테트리스 방식 단순화): 1줄 100점, 2줄 300점, 3줄 500점, 4줄(테트리스) 800점 — 여기에 현재 레벨을 곱해 레벨이 높을수록 더 높은 점수를 준다. 최고 점수는 `localStorage`에 저장해 재방문 시에도 유지한다(키 예: `tetris-best-score`).

### 4.5 다음 블록 미리보기

- **포함한다(최소 구현)**: 다음에 나올 블록 1개만 미리 보여주는 작은 미리보기 캔버스를 둔다. 7종 블록을 무작위 순서로 섞은 "가방(bag)" 하나를 만들어 순서대로 꺼내 쓰고, 가방이 비면 다시 7종을 섞어 채우는 **7-bag 랜덤 방식**을 사용한다(완전 무작위보다 특정 블록이 연속으로 나오지 않아 공정하며, 구현도 배열 셔플 한 줄로 간단하다).

### 4.6 게임오버 조건과 처리

- 새 블록을 보드 상단(스폰 위치)에 생성하려 할 때 해당 위치가 이미 고정된 블록과 겹쳐 `isValidPosition`이 `false`를 반환하면 게임오버로 처리한다.
- 게임오버 시 낙하 타이머를 멈추고, 최종 점수/레벨을 표시하는 오버레이를 띄운다.

## 5. 입력 처리

### 5.1 키보드

| 키 | 동작 |
|---|---|
| `←` / `→` | 좌/우 이동 |
| `↓` | 소프트 드롭(누르는 동안 가속 낙하) |
| `↑` | 회전(시계 방향) |
| `Space` | 하드 드롭 |
| `P` | 일시정지/재개 토글 |

- `keydown`에서 방향키/스페이스의 기본 스크롤 동작은 `preventDefault()`로 막는다. 키를 누르고 있을 때 브라우저의 키 반복(auto-repeat) 간격을 그대로 이용해 좌우 연속 이동을 구현하고, 별도의 커스텀 반복 타이머는 두지 않아 구현을 단순하게 유지한다.

### 5.2 모바일 터치 버튼

- 화면 하단에 최소한의 버튼만 배치한다: **좌, 우, 회전, 소프트 드롭(아래)**. 하드 드롭은 소프트 드롭 버튼을 일정 시간 이상 누르고 있으면(길게 누르기) 대신하거나, 별도 버튼 없이 소프트 드롭만 제공해도 무방하다(과설계 방지를 위해 하드 드롭 전용 버튼은 선택 사항으로 둔다).
- 각 버튼은 `touchstart`/`touchend`(또는 `pointerdown`/`pointerup`)로 눌림 상태를 감지하며, 좌/우/아래 버튼은 누르고 있는 동안 키보드와 동일한 반복 이동 로직을 타이머로 재현하고, 회전 버튼은 탭 1회당 1번 회전한다.
- 버튼에는 `touch-action: manipulation`을 지정해 더블탭 확대 등 브라우저 기본 제스처와 충돌하지 않도록 한다.

## 6. UI/UX 설계

- **레이아웃**: 중앙에 보드 캔버스, 옆(데스크톱 가로 폭 기준 오른쪽)에 사이드 패널을 두어 SCORE, LEVEL, LINES(제거한 줄 수), NEXT(다음 블록 미리보기)를 표시한다.
- **일시정지/재시작**: 사이드 패널 상단 또는 헤더 영역에 "일시정지" 버튼과 "다시 시작" 버튼을 상시 배치한다. 일시정지 중에는 낙하 타이머와 키 입력(재개 버튼/`P` 제외)을 무시하고 보드 위에 반투명 "PAUSED" 오버레이를 표시한다.
- **게임오버 오버레이**: 보드 중앙에 반투명 오버레이로 최종 점수와 "다시 시작" 버튼을 표시한다(2048/pixel-editor와 동일한 오버레이 패턴 재사용).
- **블로그로 돌아가기 링크**: 헤더 최상단에 `<a class="back-link" href="../../index.html">← 블로그로 돌아가기</a>`를 다른 두 앱과 동일한 위치(헤더 맨 앞)에 배치한다.
- **네온 테마**: 검정 배경(`--bg`)에 네온 강조색(`--accent`, `--accent-2`)을 쓰는 톤은 블로그·다른 두 앱과 맞추되, 테트로미노 7종 색상(`--piece-i`, `--piece-o`, `--piece-t`, `--piece-s`, `--piece-z`, `--piece-j`, `--piece-l`)을 포함한 자체 CSS 커스텀 프로퍼티를 이 앱 안에서 독립적으로 정의한다(블로그 CSS를 import하지 않음).

## 7. 반응형 고려사항

- 데스크톱(넓은 화면)에서는 보드+사이드 패널을 가로 배치(flex row)하고, 860px 이하 등 좁은 화면에서는 세로로 쌓이는 flex column 레이아웃으로 전환한다(사이드 패널이 보드 위 또는 아래로 이동).
- 보드 캔버스는 `width: min(90vw, 300px)` 형태의 상대 단위와 `aspect-ratio: 1 / 2`(10:20 비율)로 크기를 지정해 뷰포트에 맞춰 축소되도록 하고, JS에서 캔버스의 실제 렌더링 해상도(`canvas.width`/`height`)를 표시 크기에 맞춰 동기화한다.
- 모바일 터치 버튼 영역은 보드 아래에 고정 배치하고, 버튼 크기를 `clamp()` 등으로 최소 탭 영역(약 44px 이상)을 보장한다.
- 페이지 전체에 가로 스크롤이 생기지 않도록 `max-width: 100%`를 각 요소에 적용한다.

## 8. 접근성 최소 고려사항

- 일시정지/다시 시작 등 모든 버튼은 실제 `<button>` 요소로 만들어 키보드 포커스와 Enter/Space 활성화가 기본 동작으로 동작하게 한다.
- 점수/레벨/줄 수를 표시하는 사이드 패널 영역에 `aria-live="polite"`를 지정해 값 변경이 스크린 리더에도 전달되도록 한다.
- 보드 캔버스에 `role="img"`와 `aria-label`(예: "테트리스 게임 보드")을 지정해 스크린 리더 사용자에게 최소한의 맥락을 제공한다. Canvas 내부 셀 하나하나에 대한 상세 접근성 트리 구축 같은 과한 확장은 하지 않는다.
