클로드 코드와 함께 이 블로그를 프레임워크 없이 만들면서, HTML·CSS·JavaScript가 각자 어떤 역할을 맡는지 다시 한번 체감했다.

## HTML — 구조

`index.html`은 딱 껍데기 역할만 한다. 헤더, 다크모드 토글 버튼, 글이 렌더링될 `<main id="app">` 컨테이너 정도만 정의하고, 실제 콘텐츠는 전부 JavaScript가 채워 넣는다.

```html
<main id="app" class="container"></main>
```

즉 HTML은 "무엇이 어디에 들어갈 자리인지"를 정의하는 뼈대이고, 내용 자체는 담당하지 않는다.

## CSS — 표현

가독성과 다크 모드는 전부 CSS 커스텀 프로퍼티(`--bg`, `--text`, `--accent` 등)로 해결했다.

- `@media (prefers-color-scheme: dark)`로 시스템 설정을 기본으로 따르고
- `:root[data-theme="dark"]`처럼 속성 선택자로 감싸면 자바스크립트가 심은 값이 시스템 설정보다 우선 적용된다
- `overflow-x: auto`, `max-width: 100%` 같은 작은 규칙들이 모바일에서 가로 스크롤을 막아준다

같은 마크업이라도 CSS 변수 값만 바뀌면 완전히 다른 테마로 보인다는 걸 다시 확인했다.

## JavaScript — 동작

JS는 세 가지 일을 나눠서 한다.

1. **데이터 변환** — `frontmatter.js`가 `---`로 감싼 메타데이터를 파싱하고, `markdown.js`가 본문을 HTML 문자열로 바꾼다.
2. **라우팅** — `app.js`의 해시 라우터가 `#/`와 `#/post/<slug>`를 구분해 목록/상세 화면을 그린다.
3. **상태 저장** — `theme.js`가 사용자의 다크모드 선택을 `localStorage`에 저장해 재방문 시에도 유지한다.

> 프레임워크 없이 직접 짜보니, 라이브러리가 평소에 얼마나 많은 걸 대신 처리해주는지도 새삼 느꼈다.

## 정리

- HTML: 자리를 잡는다
- CSS: 어떻게 보일지 정한다
- JS: 데이터를 다루고, 상태를 기억하고, 화면을 바꾼다

셋의 역할을 분리해서 생각하니 코드가 훨씬 정리되어 보였다.
